# BM25 hybrid retrieval: decision rule (written before measurement)

Date: 2026-11-08. Committed before any BM25 or hybrid number is computed.

## Why
On the held-out Set C questions, `turkish-e5-large` found the right disclosure in the top 5 for 42/48 questions but at rank 1 for only 32/48. All 16 rank-1 misses had the right company at the top and the wrong disclosure. One manual query showed the same pattern for a country name. Embeddings capture the topic; exact words (country, counterparty, product, project names) are not ranked first. Lexical search ranks exact words.

## Method (fixed now, not tuned afterwards)
- **Documents:** the same `data/rag_docs.jsonl` as the embedding (header `SYMBOL | date | kind | headline` + normalized text).
- **Tokenizer:** Turkish lowercase (`I`→`ı`, `İ`→`i` first), then folded to ASCII (`ç ğ ı ö ş ü â î û` → `c g i o s u a i u`) so a question typed as `irak` or `sirket` matches `Irak` or `şirket` (added while writing the self-test, before any measurement), the suffix after an apostrophe is dropped (`Irak'taki` → `irak`), split on anything that is not a letter or digit, tokens shorter than 2 characters dropped, then each token is cut to its first 5 characters (fixed-prefix stemming, a standard simple choice for Turkish). No stopword list (IDF already down-weights frequent words).
- **BM25 (Okapi):** `k1=1.5`, `b=0.75`.
- **Hybrid:** reciprocal rank fusion of the full embedding ranking and the full BM25 ranking, `score = 1/(60+rank_embed) + 1/(60+rank_bm25)`, `k=60` (the usual default). Ties keep the embedding order.
- The embedding side is exactly the current system: same model, same query prefix, same cached document vectors.

## Development (dev questions: `data/rag_questions.jsonl`, 66 / 59)
- `eval_retrieval.py --method embed|bm25|hybrid` is run on the dev questions by Feyza. These numbers are optimistic (the dev questions picked the embedding model) and are used only to catch bugs.
- If the hybrid is **worse than embed on dev** in recall@5 or recall@1, stop and look for a bug before going further. A bug fix is allowed; the parameters above are not changed.
- The Set C questions are not used again (they were measured once).

## Held-out decision (new questions, written by Feyza)
- A new question set `data/rag_questions_d.jsonl`, written by Feyza under the same question guidelines, **before** any system output is seen for them. Target about 30 answerable plus a few negatives. Claude does not propose questions.
- Disclosures used must not be Set B or Set C question disclosures.
- Measured once, embed and hybrid both, same run.
- **Adopt the hybrid if** recall@1 rises by at least 2 questions and recall@5 drops by at most 1 question. Otherwise the embedding alone stays.
- Reported either way: recall@1, recall@5, wrong-same-company, and the per-question changes counted as fixed / broken.

## Amendment 1 (2026-11-08, written AFTER the dev numbers, BEFORE any new question is written)
Dev result (commit f1b36f0, 59 answerable): embed 51 / 43 (recall@5 / recall@1), bm25 55 / 44, hybrid 55 / 43. The hybrid did not trip the bug stop, but BM25 alone was at least as good as the hybrid on both metrics. The dev questions were written by reading the texts, so they may share exact words with them, which favours BM25.

Changed rule for the held-out decision (replaces "Adopt the hybrid if ..."):
- Three methods are measured once on the new questions, same run: `embed`, `bm25`, `hybrid`.
- A candidate (`bm25` or `hybrid`) qualifies if, against `embed`, recall@1 rises by at least 2 questions and recall@5 drops by at most 1 question.
- If none qualifies, `embed` stays. If one qualifies, it is adopted.
- If both qualify: the higher recall@1 wins; if they are within 1 question on recall@1, `hybrid` is adopted (it keeps the embedding's match on paraphrased questions without shared words).
- Feyza writes the new questions by hand (`scripts/write_questions.py`), not generated by an LLM: generated questions copy the text's words and would inflate BM25.
- The new questions should mix two kinds, chosen by Feyza while writing: questions that name a specific thing (country, counterparty, product) and questions that describe it in other words. The tool records which kind she meant (`kind`: `named` / `paraphrased`), and results are also reported per kind. This field is reporting only, not part of the decision.

## Honest limit
About 30 questions can show only a large effect; a gain of 2 questions is within noise. The rule is a practical bar for "worth switching", not a significance test.

## Not in this round
- Absence detection ("no such disclosure") from lexical matches. Possible next step, needs its own rule.
- Any change to the morning list or agent before the decision.
